Student Programming Evaluation

Cơ chế tính điểm Hybrid Code Confidence Scoring

Cơ chế này dùng để tính “độ tín nhiệm” cho câu trả lời hoặc code sinh ra ở trang /k/student-programming. Nguyên tắc quan trọng là không đánh đồng điểm ước lượng bằng AI với điểm chấm testcase thật.

scoreSource

Nguồn điểm: benchmark, synthetic tests, LLM judge, static-only hoặc unavailable.

isEstimated

Cho biết điểm có phải là điểm ước lượng hay không.

confidenceLevel

Mức tin cậy của cơ chế chấm: high, medium hoặc low.

Thứ tự ưu tiên chấm điểm

Pipeline chạy theo thứ tự từ đáng tin cậy nhất đến fallback:

1 Benchmark testcase thật

Ưu tiên cao nhất nếu match được dataset hoặc smoke sample.

2 Synthetic tests

Rule fallback cho các bài pure-function đơn giản.

3 LLM judge fallback

Chấm ước lượng bằng rubric khi còn đủ code để phân tích.

4 Static-only fallback

Dùng tín hiệu tĩnh nếu LLM lỗi, timeout hoặc parse fail.

5 Unavailable

Không đủ dữ liệu để chấm trung thực.

1. Benchmark testcase thật

confidence: high

Khi nào dùng

Dùng khi hệ thống tìm được sample benchmark phù hợp với câu hỏi và ngôn ngữ.

Benchmark có thể đến từ dataset đã import vào database hoặc smoke samples local như HumanEval/MBPP.

Cách match benchmark

  • Token overlap giữa câu hỏi và benchmark prompt.
  • Coverage của token benchmark được match.
  • Similarity ratio bằng difflib.SequenceMatcher.
  • Identifier overlap, ví dụ tên hàm, biến, task id.
  • Bonus nếu câu hỏi nhắc đúng entry_point.
  • Bonus nếu câu hỏi nhắc đúng task_id.
  • Bonus nhỏ cho dataset chuẩn như HumanEval/MBPP/MultiPL-E.

Nếu có signal mạnh như tên hàm hoặc task id, backend lọc candidate trước rồi mới score.

best_score >= 1.6 → nhận benchmark
best_score < 1.6  → không dùng benchmark

Cách tính điểm

Nếu match benchmark, backend chạy code trong sandbox với testcase của benchmark.

passed = total nếu sandbox status == "passed", ngược lại 0
score = round(100 * passed / total)
Ví dụ pass 
total = 5
passed = 5
score = 100
Ví dụ sandbox fail 
total = 5
passed = 0
score = 0

Metadata

{
  "scoreSource": "benchmark",
  "isEstimated": false,
  "confidenceLevel": "high"
}

Ý nghĩa: đây là điểm testcase thật, độ tin cậy cao nhất.

2. Synthetic tests từ rule fallback

confidence: medium

Khi nào dùng

Dùng khi không match được benchmark thật nhưng câu hỏi/code thuộc một số bài pure-function đơn giản mà backend nhận diện được.

Các rule hiện hỗ trợ gồm:

  • Cộng hai số.
  • Đảo chuỗi.
  • Kiểm tra số nguyên tố.
  • Giai thừa.
  • Ước chung lớn nhất.
  • Palindrome.

Cách nhận diện

Backend trích xuất ngôn ngữ, tên hàm, danh sách tham số và keyword trong câu hỏi.

Question: Viết hàm is_prime(n) kiểm tra số nguyên tố
Code: bool is_prime(int n) { ... }

Backend nhận diện rule prime_check và sinh synthetic tests cố định.

Cách tính điểm

passed = total nếu sandbox status == "passed", ngược lại 0
score = round(100 * passed / total)

Điểm này vẫn dựa trên testcase chạy trong sandbox, nhưng testcase không phải dataset chuẩn mà do rule fallback sinh ra.

Metadata

{
  "scoreSource": "synthetic_tests",
  "isEstimated": false,
  "confidenceLevel": "medium"
}

Ý nghĩa: có chạy testcase thật, nhưng testcase là synthetic fallback nên độ tin cậy trung bình.

3. LLM judge fallback

confidence: medium/low

Khi nào dùng

  • Không match benchmark.
  • Không match rule fallback.
  • Câu trả lời vẫn có code hoặc snippet đủ để phân tích.

Mục tiêu là tránh trường hợp hệ thống trả unavailable chỉ vì thiếu dataset, trong khi vẫn có thể đưa ra điểm tham khảo trung thực.

Static signals trước khi gọi LLM

  • hasCode: có code thật hay không.
  • isTestable: code có dạng hàm/lớp dễ chấm sandbox không.
  • functionName: tên hàm phát hiện được.
  • syntaxValid: Python compile được hay không, nếu là Python.
  • syntaxError: lỗi cú pháp nếu có.
  • hasEdgeCaseSignals: có nhắc đến edge case, empty, negative, zero, boundary, rỗng, âm, v.v.
  • hasBlockingInput: có pattern nhập liệu trực tiếp như input(), scanf(), cin >> không.
  • codeLength: độ dài code.

Backend cũng lọc prose thường để tránh đưa đoạn giải thích không có code sang AI judge.

Prompt judge

LLM judge nhận đề bài, câu trả lời, code trích xuất, static signals và rubric 100 điểm.

Correctness against prompt: 35
Algorithm/logic quality: 25
Edge cases: 15
Readability/maintainability: 15
Safety/performance: 10

LLM bắt buộc trả JSON strict:

{
  "score": 72,
  "rationale": "Lời giải có hướng đúng nhưng thiếu xử lý edge case.",
  "issues": ["Thiếu edge case"],
  "strengths": ["Có cấu trúc hàm rõ"]
}

Cách tính điểm

score = round(float(llm_score))
score = max(0, min(100, score))
LLM trả 72.4 → score = 72
LLM trả 120  → score = 100
LLM trả -10  → score = 0

Timeout

STUDENT_EVAL_JUDGE_TIMEOUT_SECONDS=20

Nếu env sai hoặc không set, mặc định là 20 giây.

Metadata

{
  "scoreSource": "llm_judge",
  "isEstimated": true,
  "confidenceLevel": "medium"
}

Nếu score thấp hơn 40:

{
  "confidenceLevel": "low"
}

Ý nghĩa: đây là điểm ước lượng bằng phân tích code + AI judge, không phải điểm testcase correctness.

4. Static-only fallback

confidence: low

Khi nào dùng

  • Có code để phân tích.
  • Không có benchmark/rule fallback.
  • LLM judge lỗi, timeout, parse JSON fail hoặc provider không khả dụng.

Cách tính điểm

base score = 20
Cộng điểm 
+20 nếu có code
+15 nếu code có cấu trúc testable
+10 nếu phát hiện tên hàm
+10 nếu Python compile syntax OK
+5  nếu có dấu hiệu cân nhắc edge cases
Trừ điểm 
-15 nếu Python syntax invalid
-10 nếu có blocking input pattern như input(), scanf(), cin >>

Sau đó clamp về 0–65:

score = max(0, min(65, score))

Lý do giới hạn 65: static-only không chạy testcase và không có LLM judge thành công, nên không nên cho điểm quá cao.

Có code: +20
Testable: +15
Có tên hàm: +10
Python syntax OK: +10
Không edge case: +0
Không blocking input: +0

score = 20 + 20 + 15 + 10 + 10 = 75
clamp max 65 → score = 65

Metadata

{
  "scoreSource": "static_only",
  "isEstimated": true,
  "confidenceLevel": "low"
}

Ý nghĩa: điểm tham khảo thấp tin cậy, chỉ dựa trên tín hiệu tĩnh.

5. Unavailable

confidence: low

Khi nào dùng

Backend không đủ dữ liệu để chấm trung thực, ví dụ:

  • Không có code rõ ràng trong câu trả lời.
  • Câu trả lời chỉ là mô tả/prose.
  • Không thể trích xuất snippet có đặc điểm giống code.

Cách tính điểm

score = 0
passed = 0
total = 0

Metadata

{
  "scoreSource": "unavailable",
  "isEstimated": false,
  "confidenceLevel": "low"
}

Ý nghĩa: hệ thống không cố bịa điểm khi không có đủ dữ liệu.

Hiển thị trên frontend

Frontend dùng scoreSource để hiển thị label:

scoreSource Label
benchmarkChấm bằng benchmark
synthetic_testsChấm bằng rule fallback
llm_judgeĐiểm tín nhiệm ước lượng
static_onlyĐiểm phân tích tĩnh
unavailableChưa đủ dữ liệu để chấm

Nếu isEstimated=true, UI hiển thị thêm mô tả:

Không có benchmark/testcase chuẩn, điểm này được tính bằng phân tích code + AI judge.

Ý nghĩa các mức confidence

high

Dùng cho benchmark thật. Đây là mức tin cậy cao nhất vì code được chạy bằng testcase chuẩn.

medium

Dùng cho synthetic tests từ rule fallback và LLM judge score từ 40 trở lên.

low

Dùng cho static-only fallback, unavailable và LLM judge score dưới 40.

Bảng tổng hợp

Nhánh Có chạy testcase? Có dùng LLM? scoreSource isEstimated confidenceLevel
Benchmark Có Không benchmark false high
Rule fallback Có Không synthetic_tests false medium
LLM judge Không Có llm_judge true medium/low
Static-only Không Không static_only true low
Unavailable Không Không unavailable false low

Điểm cần hiểu đúng

  • benchmark là điểm correctness thật theo testcase.
  • synthetic_tests cũng chạy testcase, nhưng testcase là rule fallback đơn giản.
  • llm_judge là điểm tín nhiệm ước lượng, không phải điểm AC/testcase.
  • static_only là điểm thấp tin cậy nhất trong các nhánh còn có code.
  • unavailable nghĩa là không đủ dữ liệu để chấm, không phải code sai.
