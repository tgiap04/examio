■ 03 · RBAC model 03 / 10

Roles & permission catalog v1

Three roles, one catalog.
Deny by default.

STUDENT

Default on signup

Learns only what a teacher granted

Studies granted flashcard/quiz sets, takes exams in allowed sessions, joins (not creates) study rooms, reads and saves word families. No AI, wallet, or content creation.

TEACHER

Granted by SYSTEM_ADMIN

Creates, shares, generates

Mutually exclusive with STUDENT. Previews only own content via owner checks; no flashcard:study / quiz:practice / exam:take. Gets wallet + Free subscription on promotion.

SYSTEM_ADMIN

Flag, combinable

Administers — no wildcard

Combines with either base role. Only it can assign roles (role:assign); self-change blocked; the last SYSTEM_ADMIN is protected.

How it is enforced

Catalog lives in libs/auth-jwt/src/permissions.ts (as const + ROLE_PERMISSIONS). Global APP_GUARDs JwtAuthGuard → PermissionsGuard, deny by default; opt-outs @Public() and @Authenticated(); @RequirePermissions(...) uses AND semantics. Ownership is a plain service where {id, ownerId} → 404. No CASL. A CI test fails if any handler lacks a declaration.

JWT: RS256 via jose@5.10, typ: at+jwt, claims iss, aud, sub, sid, roles, iat, exp (+ av, email_verified). No permissions in the token. Access 15m; refresh reloads the role from DB.

Rollback

Any failure in steps 4–10, or within the 24 h rollback window: docker compose down, remove the new volumes, checkout pre-cutover, pg_restore the step-1 dump, restore the old R2_BUCKET_NAME, start the :pre-cutover images, smoke login.
