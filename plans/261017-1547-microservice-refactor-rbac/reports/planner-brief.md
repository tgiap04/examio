## Resolved design calls (lead decisions — apply, do not reopen)
1. **DB reset**: no data migration/backfill anywhere. Rename/drop columns freely. Phase 01 replaces `prisma db push` with a fresh single baseline migration + `migrate deploy`; phase 11 replaces that with per-service baselines.
2. **Role model** (Prisma, auth-owned): `enum BaseRole { STUDENT TEACHER }`, `User.role BaseRole @default(STUDENT)`, `User.isSystemAdmin Boolean @default(false)` (replaces `isAdmin`), `RoleChangeLog` table (actorId, targetId, from, to, reason, createdAt, email snapshots). STUDENT/TEACHER mutually exclusive by construction; SYSTEM_ADMIN combinable with either.
3. **JWT**: RS256 via `jose@5.10` (CJS), `typ: at+jwt`, claims `iss, aud, sub, sid, roles, iat, exp`; `roles` = `["STUDENT"]` | `["TEACHER"]` (+ `"SYSTEM_ADMIN"`). NO permissions in token. Access 15m; refresh unchanged (opaque, AES-GCM, rotation). Refresh MUST reload role from DB.
4. **Permissions**: `libs/auth-jwt/src/permissions.ts` `as const` catalog + `ROLE_PERMISSIONS`. Global `APP_GUARD`s: `JwtAuthGuard` → `PermissionsGuard`, **deny by default**; opt-outs `@Public()` (parses token if present; replaces OptionalAuthGuard) and `@Authenticated()` (any logged-in). `@RequirePermissions(...)` AND semantics. Ownership = plain service `where {id, ownerId}` → 404. No CASL. CI test fails if any handler lacks a declaration.
5. **Permission catalog v1** (keep these exact keys):
   - > Validation Session 1 (2026-10-18): TEACHER also gets `word_family:save` (decisions.md); the list below predates it. <!-- Updated: Validation Session 1 - TEACHER += word_family:save -->
   - STUDENT: `flashcard:study`, `quiz:practice`, `exam:take`, `study_room:join`, `word_family:read`, `word_family:save`
   - TEACHER: `quizset:manage`, `flashcardset:manage`, `exam_room:manage`, `exam_session:manage`, `exam_result:view`, `content:share`, `user:search`, `ai:generate`, `ai_chat:use`, `document:upload`, `study_room:create`, `study_room:join`, `word_family:read`, `word_family:generate`, `wallet:use`, `subscription:manage`
   - SYSTEM_ADMIN: `admin:access`, `user:manage`, `role:assign`, `finance:admin`, `stats:read`, `logs:read`, `audit:read`, `page_config:manage`, `word_family:admin`
   - Authenticated (no permission, `@Authenticated()`): profile, devices, logout, me, change-password, verification.
   - TEACHER does NOT get `flashcard:study`/`quiz:practice`/`exam:take` — teacher previews only OWN content via owner checks (decisions.md). SYSTEM_ADMIN has NO wildcard.
6. **Role change flow**: only SYSTEM_ADMIN (`role:assign`); block self-change; protect last SYSTEM_ADMIN (`SELECT … FOR UPDATE` in tx); re-check actor against DB on that endpoint; write `RoleChangeLog` + `AdminAudit`; after commit call gateway `InvalidateUser(userId)` (NOT session revoke) and publish `auth.user.role_changed` via outbox. Ban still revokes sessions + `InvalidateUser`.
7. **Wallet/subscription provisioning**: only TEACHER. Register no longer creates `UserSubscription`. finance consumes `auth.user.role_changed` (to=TEACHER) → idempotently ensure Wallet(+20 welcome credits once) + Free subscription. Demotion keeps wallet (inaccessible without `wallet:use`). Bootstrapped admins get provisioning only if also TEACHER.
8. **Grant mechanism** teacher→student: reuse whitelist / invite code / public. Add to QuizSet: `accessCode`, `whitelist String[]` (+ existing `isPublic`). Entering a valid code adds the student to the whitelist (remembered). `generate-code` must NOT wipe whitelist. `users/search` TEACHER-only, no email in results, rate-limited.
9. **gRPC identity**: forward the caller's access token in `authorization` metadata and re-verify with `libs/auth-jwt` (do NOT trust bare `x-user-roles`). Service-originated calls (events, cron) use a service token signed by auth? → keep KISS: system calls carry no user and target RPCs that don't need a user; such RPCs are reachable only on the internal network. (ARCHITECTURE §5.3 to be corrected in phase 19.)
10. **WS auth**: gateway verifies the access token at HTTP upgrade from cookie `accessToken` or `Authorization` header (both visible at upgrade) + revoke/stale checks; study-room service re-verifies `handshake.auth.token`/cookie with `libs/auth-jwt` and requires `study_room:join`.
11. **Gateway**: Nest app with `bodyParser:false`, one `http-proxy-middleware@3.0.7` proxy per upstream driven by YAML; coarse `permissions:` per route prefix only (e.g. `/api/v1/ai/*` → `ai:generate`), fine checks in services; Redis Lua rate limiter (custom); `GatewayControl` gRPC (`RevokeSession`, `InvalidateUser`, `SetPageFlags`); stale check → `401 TOKEN_STALE`, revoked → `401 SESSION_REVOKED`, expired → `401 TOKEN_EXPIRED`; if Redis down: fail-open for stale check on non-admin routes, fail-closed on `/api/v1/admin/*` (log + metric).
12. **FE**: cannot read HttpOnly JWT → `/auth/me`, login, refresh return `{ user, roles, permissions }`; `useCan(perm)`, `<RequirePermission>` route guard, permission-driven sidebar, role-based `/k` redirect (TEACHER → `/k/ai-tool`, STUDENT → `/k/my-materials`, admin-only → `/admin`), 403 page, refetch store + reset feature caches after TOKEN_STALE refresh (retry once). Generate the `Permission` TS union from `libs/auth-jwt` into `examio-fe/src/types/permissions.generated.ts` with a CI diff check. Fix `User.id` type to `string`.
13. **Versions**: Node 22 images; Prisma 6.19.x; per-service Prisma `generator client { provider = "prisma-client" output = "../src/generated/prisma" }` + `@prisma/adapter-pg` + DB role `ALTER ROLE <svc>_svc SET search_path = <svc>`; ts-proto `nestJs=true,addGrpcMetadata=true` (no `outputServices`); buf v2; Python stubs via `grpc_tools.protoc`; custom webpack config to bundle node_modules (spike in phase 16).
14. **Mobile** (`examio-app`, separate repo, not in this checkout): phase 18 only; iOS + Android parity mandatory (CLAUDE.md).
15. **Repo rules**: plans only in `/plans`; never commit without user approval; deleting DB records with R2 images must delete R2 objects too; no N+1 (batch RPC `GetUsersByIds`); match file style; files < 200 lines.
